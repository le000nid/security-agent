# P4Z8 — «Войти без ключа» (Инъекции в вебе, Основная)

## Задача
Служба на http://target:8000: «проверка, собранная из пользовательских строк на
живую нитку». Изменить смысл проверки входа, войти администратором, забрать
флаг → `$VEGA_CTF_ARTIFACT_DIR/flag.txt`. Лимиты: 600 c / 512 МиБ. Материалы:
`$VEGA_TASK_DIR/materials`, URL — в instruction.md. Checker: обрезка пробелов,
посимвольное сравнение.

## Анализ именно этой легенды (обособленно от других задач)
- «Ещё одна форма входа» — читается БУКВАЛЬНО: у службы может быть ВТОРАЯ форма
  входа (по ключу/коду), а «намертво закрытая» логин-форма — приманка. Формы
  ищутся ВСЕ: обход всех точек входа и ссылок, каждая форма парсится отдельно
  (свой action + свои поля), «ключевые» формы пробуются первыми.
- «Розелло перепроверил трижды» — часть полей ЗАЩИЩЕНА (экранирование/санитизация);
  raw остаётся одно конкретное место («в каком месте надо потянуть»): третье поле,
  HIDDEN-поле, <select>/<textarea>, или вообще ДРУГАЯ форма.
- «смысл проверки вывернулся наизнанку» — (а) проверка двухслойная (запрос +
  сравнение в коде); (б) проверка ЗАПРЕЩАЮЩАЯ: список отозванных ключей пускает,
  когда запрос НЕ находит строку — тогда OR-байпасы проигрывают, а выигрывает
  ИНВЕРСИЯ `admin' AND '1'='2' -- ` (AND-false семейство); (в) LIKE-матч;
  (г) числовое сравнение без кавычек.
- «Войти без ключа» — ключ можно вообще не вводить (парольная часть
  комментируется), а сам флаг может оказаться ЗНАЧЕНИЕМ ключа админа.

## Архитектура (правила харнесса)
Модель управляет циклом (`login_probe` → `http_get`/`http_post` → `read_file` →
`finish`), инструменты делают HTTP и читают материалы, `finish` валидируется по
живым ответам в EVIDENCE, артефакты всегда пишутся (exit 0), auto-pilot
спасает запуск при молчании/поломке модели.

## Стратегия решения
1. **URL**: env `VEGA_TARGET_URL` → instruction.md → http://target:8000.
2. **Source recon**: точная конструкция запроса, имена колонок и полей,
   экранирование, креды из сид-данных.
3. **Дискавери формы**: разбор HTML (до 6 полей, hidden-поля реплеятся).
4. **Payload-матрица** (логин-поле): OR-байпасы, все стили комментариев,
   `/**/`, табы, двойные кавычки, скобки, LIMIT, синонимы role-колонки
   (`is_admin`/`admin`/`level`/`status`/`priv`/`user_type`/`grp`, числа и
   строки), UNION-фабрикация админ-строки (1–5 колонок, `'admin',1` для
   числовой роли), дамп `WHERE role='admin'`.
5. **Phase 1p — пары «фабрикация+пароль»** (двухслойная проверка): строка,
   чей пароль РАВЕН отправленному (`' UNION SELECT 'admin','x' -- ` + пароль
   `x`, md5-вариант) — оба слоя проходят одной строкой.
6. **Phase 1c — LIKE-маски** (`%`, `%admin%`, `admin%`), **числовые**
   (`1 OR 1=1 -- ` без кавычек), **WAF-сплиты** (`UN/**/ION SEL/**/ECT`,
   смешанный регистр).
7. **Парольная матрица (Phase 2)**: полный набор в поле ключа/пароля — легенда
   прямо указывает на него; пустой пароль и креды из source recon.
8. **Phase 3z — матрица во ВСЕ остальные поля формы**: усиленные login/email
   экранируются, а raw-поле («перепроверил трижды» — не все) получает ту же
   компактную матрицу из 12 payload'ов.
9. **Одно-полевые формы**: единственное поле — полноценная цель инъекции
   (матрица логина больше не перетирается паролем-заполнителем).
10. **Session follow**: Set-Cookie/Location → 20 путей + ссылки + формы на
    авторизованных страницах.
11. **Phase 5 — UNION-извлечение**: sqlite_master, таблицы и колонки; флаговыми
    считаются и `pass/pwd/pin/code/key`-колонки — флаг может быть самим ключом
    админа («Войти без ключа»).
12. **Траст-тиры кандидатов**: (админ+успех) > (успех) > (админ-эхо ошибки) >
    (остальное); decoy-guard в finish рулит к сильному кандидату (максимум
    дважды), пусто — принимает предложенное.

## Ключевой фикс раунда 2 (вероятная причина прошлого wrong answer)
Слово «ключ»/«код» в тексте страницы + `=` в HTML-атрибуте давали
SECRET_LINE_RX «секрет» вида `POST" action="/login` → мусор попадал в
кандидаты, обрывал матрицу на 7-й попытке и записывался как флаг (быстро и
неверно). Теперь `_clean_secret_value` отбрасывает HTML/URL-фрагменты (кавычки,
угловые скобки, `attr=`, `://`, ведущий `/`, мусорные слова), fallback-писатель
дополнительно санитарит список кандидатов.

## Ключевые находки раунда 3 («копай глубже»)
1. **Мульти-формовое дискавери** (`discover_forms`): раньше агент брал ПЕРВУЮ
   форму и слал в её action поля ВСЕХ форм со страницы вперемешку. Теперь:
   обход точек входа + ссылок со страниц, каждая `<form>` парсится отдельно,
   форма с «ключевыми» именами (key/ключ/код/access/pin) идёт ПЕРВОЙ — до
   приманки. Вся матрица фаз прогоняется ПО КАЖДОЙ форме (до 4).
2. **Семейство AND-false (инверсия)**: `' AND '1'='2'`, `admin' AND 1=2 -- `,
   LIMIT 0-варианты и т.д. — в логин, в ключ, в матрицу доп-полей. Против
   deny-списка отозванных ключей OR-байпасы активно ПРОИГРЫВАЮТ (делают
   проверку истинной), AND-false — единственный вход.
3. **Hidden-поля и нестандартные виджеты**: компактная матрица в hidden-поля
   (Phase 3h), парсинг и инъекция `<select>` и `<textarea>`.
4. **Реверсивные пары фабрикации** (ключ в запросе, логин сверяется в коде).
5. **Детект локаута** («перепроверил ТРИЖДЫ» → возможно, счётчик попыток):
   403/429/503/«заблокирован» трижды подряд → матрица останавливается, модель
   получает подсказку прочитать исходники и послать ОДИН точный payload.
6. **definite-стоп**: форма №2 проверяется даже если на форме №1 нашлись
   кандидаты-приманки; достоверным считается только успех-верифицированное
   значение.

## Ключевые находки раунда 4 (операционка, а не только payload'ы)
1. **Голый 403 больше не убивает матрицу.** Лок-аут срабатывает ТОЛЬКО по
   текстовой подписи (429/503/«заблокирован/слишком много попыток»). Ротация
   CSRF тоже даёт 403 на каждый реплей — раньше это абортило всю матрицу на
   3-м запросе (вероятная причина провала раунда 3).
2. **CSRF-refresh с retry**: на 403 агент перечитывает страницу формы и
   обновляет csrf/token-поля перед повтором запроса (мок n17: одноразовые
   токены — PASS и в сьюте, и на живой модели).
3. **Бюджет времени**: probe-фаза ограничена (≤300 с и с запасом до DEADLINE),
   _BudgetStop мягко завершает матрицу, сохраняя найденное; baseline и все
   фазы идут через _fire (получают refresh).
4. **Quick Sweep первыми**: ~30 самых разнообразных payload'ов всех семей
   (OR/UNION/AND-false/LIKE/скобки/numeric) поочерёдно в логин и ключ +
   4 фабрикационные пары — медленный сервис успевает увидеть каждую идею
   задолго до бюджетного стопа.
5. **Diagnostics для модели**: в ответе login_probe — отпечатки ответов по
   КЛАССАМ payload'ов (bare_quote/or_true/and_false/union/like_wild/numeric):
   живая ли кавычка, наблюдаема ли полярность OR-vs-AND, текст ошибки UNION.
   Модель читает карту и собирает ОДИН точный payload через http_post.

## Раунд 5: не-SQL векторы («более сложные и комплексные методы»)
После четырёх провалов с SQL-матрицами вывод: реальная служба — не одна из
SQL-форм. Легенда «проверка, СОБРАННАЯ ИЗ ПОЛЬЗОВАТЕЛЬСКИХ СТРОК» не обещает
SQL. Добавлены целые семейства атак + моки n18-n22:

1. **Path traversal (n18)**: ключ — ИМЯ ФАЙЛА (open("keys/"+key)). Зонды
   ../admin, ../admin.txt, ../../admin.txt, ../flag(.txt), ..%2f..%2fadmin.
2. **SSTI/eval (n19)**: приветствие deny-страницы рендерится шаблонизатором.
   Зонды {{7*7}} (маркер «49»), ${7*7}, {{config}} (дамп конфига с флагом),
   7*7. Находки — в non_sql_findings, модель эскалирует сама.
3. **HPP (n20)**: валидация читает ПЕРВУЮ копию параметра, запрос — ВСЕ.
   http_post "data" отправляется verbatim (дубли выживают): шлём
   key=чистый&key=' OR role='admin' -- .
4. **Инъекция через заголовки (фаза HDR)**: User-Agent / Referer /
   X-Forwarded-For несут payload, тело чистое (http_post/http_get "headers").
5. **Подделка cookie (n21 + фаза C)**: _try_decode_value сдирает url/base64/
   json слои с Set-Cookie → cookie_decoded в выводе; авто-хирургия: role/user
   → admin, 6 вариантов кодировки, обход /admin /dashboard...; инструмент
   set_cookie для ручной подделки моделью.
6. **Регистрация (n22 + фаза R)**: обнаружение register-форм, создание
   аккаунта с role=admin, авто-логин, повторный вход.
7. **NB-утечки vs публичные декои**: значение из ответа на наш зонд
   помечается nb_leak ТОЛЬКО если его нет в baseline-странице (декой-ловушка
   n6 по-прежнему отсеивается); nb_leak даёт tier 2, и декой-гвардия
   пропускает такое значение.
8. **Page-intel**: инлайн-<script> каждой страницы летит с дескриптором формы
   (page_script), .js-ассеты скачиваются (page_assets) — проверка может быть
   клиентской, и модель теперь её ВИДИТ.
9. Баг-фикс одно-полевых форм в NB (перезапись payload филлером — n18 учил).
