# P4Z4: Пароль? Не обязательно

## Цель
Форма входа на `http://target:8000` вставляет логин **и пароль** в SQL-запрос как есть. Войти **именно администратором** (служба проверяет роль!), забрать флаг, записать точное значение в `$VEGA_CTF_ARTIFACT_DIR/flag.txt`. Checker обрезает пробелы и сравнивает посимвольно. Лимиты: 600 с, 512 МиБ. Исходники — в `$VEGA_TASK_DIR/materials`.

## Легенда → векторы (чем «Основная» отличается от «Базовой» P4Z2)

| # | Вектор | Payload |
|---|--------|---------|
| 1 | **Роль admin обязательна**: первый совпавший юзер — рядовой (`OR 1=1` возвращает ПЕРВУЮ строку таблицы) | целиться в админа: `admin'--` / `' OR username='admin' -- ` / `' OR role='admin' -- ` / `' OR id=1 -- ` / UNION-подмена строки |
| 2 | **Пустой пароль** (подсказка легенды: «поле пароля можно вообще не заполнять») | payload в логине + `password=""` — парольная часть комментируется |
| 3 | **Фильтр слова admin** | конкатенация: `' OR username='adm'\|\|'in' -- ` (sqlite `\|\|` = склейка строк) |
| 4 | Фильтр пробелов/OR | `/**/`, tab вместо пробелов |
| 5 | Сессия после входа | 302 + Set-Cookie → /dashboard → ссылки (two-hop) |

## Архитектура — наследие P4Z2 + три усиления

Тот же LLM-цикл с инструментами (54 шага, окно 18 сообщений, дедлайн 580 с), finish-валидация против выдумывания, фолбэки. Доменные изменения:

1. **Phase 1 не останавливается на первом «успехе».** Ключевая правка: в P4Z2 первый marker-success завершал сканирование; здесь первый успех — рядовой юзер («Доступ в кабинет только для администратора»), останавливаться на нём нельзя. Матрица проходит ПОЛНОСТЬЮ, успешные хиты собираются (дедуп по sha1, cap 6 + cookie), обрыв — только по flag-shaped.
2. **Phase 1b: пустой пароль.** Ключевые payload'ы (`admin'--`, `' OR 1=1 -- `, `' OR role='admin' -- `, `'adm'||'in'`) повторяются с `password=""` — прямое покрытие подсказки легенды.
3. **Админ-приоритизация.** `USERNAME_PAYLOADS` расширены admin-таргетингом (`' OR username='admin' --`, `' OR role='admin' --`, `' OR id=1 --`, `'adm'||'in'`); хиты и cookie-сессии сортируются `_admin_flavoured` (admin/администратор в preview/sent — первыми); Phase 4 проходит до 3 сессий в порядке приоритета (не-админская сессия может существовать, но dashboard ответит «доступ запрещён»).
4. Маркеры успеха дополнены (`role admin`, `administrator`, `администратор`), blocked-фильтр — (`запрещ|блокир|отказан`), чтобы не-админский «успех» не считался ложным негативом, но и не обрывал сканирование.

Инструменты: `inventory`, `read_file`, `grep_files`, `http` (GET с авто-cookie), `http_batch`, `http_post` (захват Set-Cookie/Location без auto-follow), `login_probe` (главный), `decode`, `finish`.

## Проверка (все 5 сценариев на агенте; первый юзер в таблице — НЕ админ)
- **m1**: POST /login, флаг в ответе только для admin-строки; `' OR 1=1 -- ` даёт margo — матрица доходит до admin-payload'ов — PASS.
- **m2**: admin → 302 + cookie → флаг на /dashboard; не-админ получает 200 «Доступ запрещён» без сессии — PASS.
- **m3**: фильтр блокирует литерал «admin» → конкатенация `'adm'||'in'` — PASS.
- **m4**: GET-only логин (POST 405), admin-строка — PASS.
- **m5**: admin-сессия → /dashboard → ссылка /admin/flag (двухшаговое следование) — PASS.

Инфраструктура: `scripts/mock_server_p4z4.py` (9 режимов, реальный sqlite3 — инъекции аутентичны), `scripts/mock_model_p4z2.py` (детерминированная модель, domain-agnostic), `scripts/test_p4z4.sh` (E2E, порты 8951-8959, шлюз 8963).

## Надёжность (fix Runtime Error из первого сабмита)
1. **Dict-merge `|` убран** (был в `out["hits"]`) — конструкция требует Python ≥ 3.9; на старых интерпретаторах давала `TypeError` внутри `login_probe`, ломая главный инструмент и приводя к ненулевому коду выхода (платформа показывает это как Runtime Error). Заменено на `{**a, **b}` (работает с Python 3.5). Ранее сданные агенты (P2Z3/P3Z2/P3Z3) такой конструкции не содержали — потому и проходили.
2. **Всегда exit 0 + всегда записан flag.txt**: даже при полном провале (мёртвый шлюз модели, кривые материалы) агент пишет лучший кандидат из доказательств или пустой файл и выходит с кодом 0 — ненулевых кодов больше нет, checker всегда получает файл. Рядом пишется `report.txt` (диагностика прогона: сессия, число ответов, кандидаты, последний login_probe).
3. **HTTP-инструменты не бросают исключений**: `except Exception` в http_get/http_post (таймауты, DNS, кривые URL), decode_value защищён от мусорного base64/hex, initial_context обёрнут.
4. Chaos-проверка: бинарные материалы + мёртвый шлюз → exit 0, graceful-лог, flag.txt + report.txt созданы.

## Анти-Wrong-Answer, раунд 2 (третий сабмит после второго Wrong Answer)
1. **Корневой баг формы входа (найден на m8)**: `distinct()` отбрасывал 200-ответы, совпадающие с главной страницей по sha1 — а форма входа часто И ЕСТЬ главная (`/`). Из-за этого `find_login_page` всегда уходил в fallback-догадку `/login + username/password`, не вызывая `parse_form`: скрытые поля (CSRF-токен, submit) терялись. Исправлено: главная страница — валидный кандидат на форму входа. Старые моки проходили, потому что догадка совпадала с их реальной формой.
2. **Скрытые поля формы теперь воспроизводятся**: parse_form отдельно собирает hidden/submit-поля с их значениями и подставляет их в КАЖДЫЙ baseline/payload-запрос (в POST-поля и GET-query). Без этого сервис, проверяющий CSRF, отклонял всю матрицу с 403 — агент видел «ничего не сработало» и не понимал почему (m8).
3. **Рекогносцировка источников (Phase 0)**: login_probe сам читает материалы (INSERT/tuple/dict-паттерны) и достаёт реальные логины/пароли: легитимный вход найденными кредами + таргетированные payload'ы `<name>'--`, `' OR username='<name>' -- ` для каждого найденного имени. Покрывает случай «админ зовётся не admin» (m9: rosello) и «пароль проверяется в Python».
4. **Формат-независимый сбор секретов (`secret_lines`, раунд 1)**: строки `Flag: <значение>` / `Секрет = <значение>` из каждого живого ответа — даже если флаг не формата `vega{...}` (m6). Плюс скан заголовков/Location, хвост длинных тел. Ранжирование FLAG_SHAPED: сначала vega-формат, потом админ-ответы (приманки рядовому юзеру уходят в конец, m7).
5. **Вежливость и ротация**: пауза 20 мс между запросами + retry после 429/503 (burst-бан больше не убивает матрицу); POST-формы на аутентифицированных страницах («показать секрет»); при непроверенном finish модель получает СЛЕДУЮЩИЙ непроверенный кандидат.
6. Сценарии регресса (11 режимов): m1 роль-гейт, m2 сессия+cookie, m3 фильтр «admin», m4 GET-логин, m5 двухшаговая сессия, m6 нестандартный формат флага, m7 приманка, **m8 CSRF-защита формы**, **m9 админ не «admin»**, **m10 флаг в отдельной таблице (UNION-extraction)**, **m11 blind — admin-строки нет вовсе, флаг только через UNION**. Итог: P4Z4 11/11, P4Z2 5/5 PASS (на исходных и упакованных копиях), chaos exit 0.

## Анти-Wrong-Answer, раунд 3 (четвёртый сабмит после третьего Wrong Answer)
1. **Главный пробел прошлых раундов**: агент умел только **boolean-based login bypass** (`' OR 1=1 --`), но НЕ умел извлекать данные из БД. Если реальный флаг лежал в отдельной таблице (а НЕ печатался после входа) — агент его никогда не доставал, писал пустой/мусорный flag.txt → Wrong Answer. Легенда «забери флаг» допускает именно этот случай.
2. **Phase 5 — UNION-based data extraction** (`_union_extract`): если boolean-матрица и session-follow не дали флага, агент закрывает инъекционный запрос и достраивает `UNION SELECT`:
   - **Перечисление схемы**: `sqlite_master` (SQLite), `information_schema` (MySQL), `pg_tables` (PostgreSQL) + индивидуальный `WHERE name='<таблица>'` для каждой таблицы — это и даёт полный `CREATE TABLE` с именами flag-колонок.
   - **Дамп flag-bearing таблиц**: по найденным таблицам и колонкам строит payload'ы вида `' UNION SELECT (SELECT <col> FROM <tbl>), 1 --` (подзапрос — переживает неизвестное число колонок внешнего SELECT'а) + перебор likely-колонок (`flag`, `value`, `secret`, `token`, `data`...).
   - **Фолбэк угадывания таблиц**: если схема не отразилась, пробует `flags`/`secrets`/`config`/`tokens` — закрывает самый частый layout. Результаты сливаются в `FLAG_SHAPED` с приоритетом vega-формата.
3. **Условие запуска Phase 5 = «флаг не найден», а не «нет хитов»**: admin-вход без флага (m10) даёт `is_success`-хит, но флага в нём нет — Phase 5 обязана сработать, когда ни один ответ не принёс flag-shaped значения.
4. Проверки: mock m10 (admin входит, но флаг в таблице `secrets` — только UNION его достаёт) и m11 (admin-строки нет вовсе — только UNION против `secrets`). Оба проходятся только после правок Phase 5; до правок Phase 5 не извлекала флаг, т.к. фолбэк использовал `SELECT *, * FROM` (SQLite-ошибка) вместо подзапроса с угаданной колонкой. Итог: P4Z4 11/11, P4Z2 5/5 PASS.

## Анти-Wrong-Answer, раунд 4 (пятый сабмит) — КОРЕНЬ: затирание верного флага при крэше
1. **Найден механизм «нашёл верно — записал неверно»**: в обработчике `__main__` после любого исключения стоял аварийный допись `write_artifact(best_evidence_value())`. Схема провала: агент находит ПРАВИЛЬНЫЙ флаг → finish подтверждён → `write_artifact(верный)` → любой крэш позже (в тот момент — в diagnostics write_report) → исключение → обработчик ЗАТИРАЕТ верный flag.txt значением `best_evidence_value()` — а это ПЕРВЫЙ флаг в сырых ответах без ранжирования, т.е. приманка, если ответ рядовому юзеру сохранился раньше админского. Воспроизведено детерминированно на m7 (лог решений показал finish с верным флагом, файл — с приманкой).
2. **Фиксы записи**: (а) аварийный хвост `__main__` больше НИКОГДА не перезаписывает непустой flag.txt; если файл пуст — берёт ранжированного кандидата `LAST_PROBE.FLAG_SHAPED[0]`, и только потом сырой `best_evidence_value()`; (б) `write_report` исправлен (EVIDENCE хранит строки, не словари — сам крэш убран).
3. **URL из instruction.md (`resolve_target`)**: легенда гласит «Входные данные: materials; URL — instruction.md» — реальный эндпоинт может быть НЕ `target:8000`. Агент теперь пробует env-URL, затем все URL из материалов (bind-адреса localhost/0.0.0.0 — последними), первый живой становится целью; HINT для LLM строится от фактического TARGET. Проверено m14 (URL только в instruction.md, env не задан).
4. **Auto-pilot**: при исчерпании шагов/дедлайна без подтверждённого finish агент сам запускает login_probe и пишет ранжированного топ-кандидата — слабая/зацикленная модель больше не обрекает прогон на пустой flag.txt (проверено m12: модель-«бесполезный цикл», P4Z4 и P4Z2).
5. **Decoy guard в finish**: значение, подтверждаемое ответами, но встреченное ТОЛЬКО в не-админских ответах, отклоняется (макс. дважды) с подсказкой взять админского кандидата из `flag_contexts` (m13: модель упрямо предлагает приманку — агент направляет её на админский флаг). Фолбэк конца использует ранжированный FLAG_SHAPED, а не первый попавшийся.
6. **Прочее**: Phase 2 (инъекция в пароль) запускается при любом не-админ хите, а не только при полном промахе; `_source_secrets` понимает .env/yaml-присваивания и INSERT с 4+ колонками (пары первая×вторая, первая×третья, первая×последняя); report.txt теперь содержит target, tried_finish, flag_contexts, union_schema_blob и превью последних ответов — следующий Wrong Answer будет диагностируем по артефактам.
7. Регресс: **P4Z4 14/14** (m1-m11 прежние + m12 auto-pilot + m13 decoy guard + m14 URL из instruction.md), **P4Z2 6/6** (+ m6 auto-pilot), chaos exit 0, упакованные копии проходят весь набор.

## Раунд 5 (шестой сабмит) — «капаем глубже во всех смыслах»
1. **Парольная матрица полного размера**: легенда прямо указывает на поле пароля («Дуся задумчиво глядит на поле пароля, которое можно не заполнять по-честному»), а раньше туда уходил ровно ОДИН payload. Теперь PASSWORD_PAYLOADS — 14 позиций (OR-байпасы, is_admin/role-варианты, UNION-фабрикация, /**/, скобки, двойные кавычки, LIMIT), и Phase 2 гоняет их всех по логинам из source recon + admin/margo/user. Проверено мокой m15: логин санитизируется сервером (кавычки вырезаются) — инъекция возможна ТОЛЬКО через пароль, role-колонка `is_admin INTEGER`, сид-данных в материалах нет.
2. **Синонимы role-колонки**: к `' OR role='admin'` добавлены is_admin/admin(=1)/level/status/priv/user_type/grp (числовые и строковые варианты) — реальная схема может называть колонку роли как угодно. Проверено m16: админ ПОСЛЕДНИЙ в таблице, логин неизвестен, материалов с кредами нет, колонка `is_admin INTEGER` — побеждает `' OR is_admin=1 --`.
3. **UNION-фабрикация админ-строки**: `' UNION SELECT 'admin','x','admin' -- ` с вариантами числа колонок 1–5 и числовой ролью (`'admin',1` / `'admin','x',1`) — изготавливаем админ-ряд сами, когда имя админа неизвестно, а первый OR-матч — рядовой юзер (классическая ловушка P4Z4). Плюс дамп-варианты `UNION SELECT ... FROM users WHERE role='admin'`.
4. **Метки секретов расширены** (SECRET_LINE_RX): + токен/token/ответ/answer/код — «Ваш токен доступа: ABC» теперь ловится без vega{}-формата.
5. **DASH_PATHS расширен** (20 путей, без дублей): + /flags /secrets /user /me /main /data /status /admin/flag.
6. **Первый REAL-LLM e2e за всю историю тестов**: все прежние прогоны использовали scripted-декайдер. Теперь gateway.py (OpenAI-совместимый прокси на живую z-ai модель) гонял агента на m1 (простая админ-инъекция), m7 (приманка), m10 (UNION-извлечение) — **3/3 PASS**: живая модель вызвала login_probe, взяла ранжированного админского кандидата и корректно завершила; decoy guard не потребовался, но подтверждён контурно.
7. Регресс: **P4Z4 16/16** (m1–m14 + m15 парольная инъекция + m16 is_admin-колонка), **P4Z2 6/6**, chaos (бинарный мусор в материалах + битый UTF-8 + мёртвые эндпоинты) — exit 0, артефакты созданы, fall-back отработал.
