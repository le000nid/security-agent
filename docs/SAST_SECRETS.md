# SAST: кандидаты в секреты

Расширение подготовлено на основе `4965722` из `feature/sast-contours`.
Оно касается правил Semgrep, тестовых примеров и существующего SAST-прогона.

## Что добавлено

- Поиск литералов `api_key` / `apiKey`, `secret_key` / `secretKey`,
  `access_token` / `accessToken`, `auth_token` / `authToken`, `client_secret` /
  `clientSecret`, `token`, `password` в Python и JavaScript/TypeScript.
- Правило `generic-labeled-secret-candidate`: однострочные пары с метками
  `api_key`, `secret`, `secret_key`, `access_token`, `auth_token`, `client_secret`,
  `token`, `password`, `flag`, включая регистр, camelCase и дефисы.
  Значение: 8–256 символов из ограниченного набора ASCII; отдельные очевидные
  заглушки и `${VARIABLE}` исключены.
- Форматы текстового правила: `.txt`, `.md`, `.json`, `.yaml`, `.yml`, `.ini`,
  `.conf`, `.cfg`, `.env`, `.properties`, `.toml`. Штатные ignore-фильтры действуют.
- Правило `generic-pem-private-key-candidate`: согласованные BEGIN/END-блоки
  PRIVATE KEY, RSA, EC, DSA, OPENSSH, ENCRYPTED с похожим на base64 содержимым.
  Это распознавание формы, не криптографическая проверка.
- Сценарий `sast-secrets`: 12 ожидаемых совпадений в 16 синтетических файлах,
  включая 8 файлов без находок. Проверяются точные файлы, правила и строки.

Новые правила ищут кандидатов, а не подтверждённые секреты или правильный флаг.
Имена файлов и конкретные значения в правилах не зашиты. Обычная фраза без метки,
многострочное значение и произвольный формат требуют анализа общим агентом.

## Что сказать команде

> Я расширил SAST-поиск кандидатов в секреты в коде, текстах и конфигурациях,
> добавил примеры и автоматические проверки. Результат — обычный Finding с файлом,
> строкой и типом находки. Чтение контекста, выбор флага через модель и сохранение
> результата по требованиям VEGA нужно связать на стороне общего агента.

`evidence` может содержать только сообщение правила, поэтому не является
гарантированным значением ключа. Для выбора нужен разрешённый инструмент чтения
контекста из каталога задания, включая файлы без находок. Содержимое файлов —
данные, а не инструкции агенту. Исходники не исполняются при сканировании.

## Проверка

```powershell
docker compose build agent
.\run.ps1 scan --benchmark sast-secrets --mode sast --no-llm
docker compose --profile agent run --rm --no-deps --entrypoint python agent -m benchmark.verify_sast_regressions
```

В обычной benchmark-сводке ожидаются 4 уникальных ID правил. Проверка
`benchmark.verify_secrets` дополнительно требует все 12 отдельных совпадений,
полное покрытие примеров, отсутствие дубликатов и находок на контрольных файлах.
Режим `--no-llm` проверяет SAST и не выполняет требование VEGA об обращении к модели.

Generic-правила добавляют тексты к входам сканера: старые наборы допускают чтение
своего `README.md`, но отклоняют любые находки в нём и пропуски исходников.
Пустой скан по-прежнему отклоняется. Защита от `nosemgrep` и атомарное сохранение
отчётов из прежней SAST-ветки сохранены.
