# VEGA P4Z8 agent («Войти без ключа»)

`vega_p4z8/` — пятый автономный экспорт для тестовой системы VEGA и самое
развитое звено SQLi-домена ([P4Z2](VEGA_P4Z2.md), [P4Z4](VEGA_P4Z4.md)):
«проверка, собранная из пользовательских строк на живую нитку» — изменить
смысл проверки входа, войти администратором, забрать флаг в
`$VEGA_CTF_ARTIFACT_DIR/flag.txt`. Проверка не обязана быть SQL: агент несёт
полный пул векторов — SQLi-матрицы, инверсию deny-списков, пары для
двухслойных проверок, path traversal, SSTI/eval, HPP, инъекцию через
заголовки, подделку неподписанной cookie и регистрацию админа. Экспорт не
меняет SAST/DAST pipeline и поставляется отдельным архивом без зависимостей
(только стандартная библиотека Python).

Все шесть экспортов собираются одной командой:

```powershell
python scripts/build_vega.py
```

Результат: `dist/security-agent-vega.zip` (базовый агент),
`dist/security-agent-p3z2.zip`, `dist/security-agent-p3z3.zip`,
`dist/security-agent-p4z2.zip`, `dist/security-agent-p4z4.zip` и
`dist/security-agent-p4z8.zip` (P4Z8). В корне каждого архива — ровно
`run.sh`, `agent.json`, `agent.py`, `strategy.md`.

## Архитектура

Тот же LLM-цикл с инструментами (54 шага, окно 18 сообщений, дедлайн 580 c),
finish-валидация против выдумывания, graceful-фолбэки, всегда exit 0 и
`report.txt` рядом с flag.txt. Поверх домена P4Z4 агент несёт **пять раундов
соревновательных итераций** (стратегия `vega_p4z8/strategy.md`, регресс
22 мок-кейса n1–n22 на автономных копиях):

1. **Quick Sweep первыми**: ~30 самых разнообразных payload'ов всех семей
   (OR/UNION/AND-false/LIKE/скобки/numeric) поочерёдно в логин и ключ + 4
   фабрикационные пары — медленный сервис успевает увидеть каждую идею до
   бюджетного стопа; `_BudgetStop` мягко завершает матрицу, сохраняя
   найденное (бюджет probe-фазы ≤300 c с запасом до DEADLINE).
2. **Мульти-формовое дискавери** (`discover_forms`): обход точек входа и
   ссылок со страниц, каждая `<form>` парсится отдельно (свой action + свои
   поля), «ключевые» формы (key/ключ/код/access/pin) идут первыми — до
   приманки; вся матрица прогоняется по каждой форме (до 4). В mutating-режиме
   403 не убивает матрицу (ротация CSRF тоже 403ит) — `login_probe`-lockout
   только по текстовой подписи (429/503/«заблокирован» ×4 подряд).
3. **Инверсия (AND-false)**: deny-список отозванных ключей пускает, когда
   запрос НЕ находит строку — OR-байпасы проигрывают, `' AND '1'='2` /
   `admin' AND 1=2 --` выигрывают; семейство идёт в логин, в ключ и в матрицу
   доп-полей. **LIKE-маски** (`%admin%`), **числовые** (без кавычек),
   **WAF-сплиты** (`UN/**/ION SEL/**/ECT`, смешанный регистр).
4. **Phase 1p/2p — пары «фабрикация+пароль»** для двухслойной проверки
   (запрос возвращает строку, код сверяет пароль): `' UNION SELECT
   'admin','x' -- ` + пароль `x`, md5-вариант; реверсивные пары (ключ в
   запросе, логин сверяется в коде). **Phase 3z/3h** — компактная матрица
   во все оставшиеся и hidden-поля; `<select>`/`<textarea>` парсятся и
   инъектируются; одно-полевые формы — полноценная цель.
5. **CSRF-refresh с retry**: на 403 перечитывается страница формы, токены
   обновляются, запрос повторяется — одноразовые токены не убивают матрицу.
6. **Не-SQL векторы (Phase NB и далее)**: path traversal (ключ — имя файла),
   SSTI/eval (`{{7*7}}` → маркер «49», `{{config}}` — дамп конфига), HPP
   («data» уходит verbatim — дубли выживают), инъекция через заголовки
   (User-Agent/Referer/X-Forwarded-For), подделка неподписанной cookie
   (`_try_decode_value` сдирает url/base64/json слои → cookie_decoded;
   авто-хирургия role/user → admin, 6 вариантов кодировки; инструмент
   `set_cookie`), регистрация аккаунта с role=admin.
7. **NB-утечки против публичных decoy**: значение из ответа на зонд
   помечается `nb_leak` только если его нет в baseline-странице — декой из
   страницы ошибки (n6) отсеивается; **траст-тиры**: (админ+успех) >
   (успех) > (nb_leak) > (админ-эхо ошибки) > (остальное); decoy-guard в
   `finish` рулит к сильному кандидату (максимум дважды).
8. **Page-intel**: инлайн-`<script>` каждой страницы летит с дескриптором
   формы (page_script), .js-ассеты скачиваются (page_assets) — проверка
   может быть клиентской; **diagnostics** в ответе login_probe — отпечатки
   ответов по КЛАССАМ payload'ов (bare_quote/or_true/and_false/union/
   like_wild/numeric): живая ли кавычка, наблюдаема ли полярность OR-vs-AND,
   текст ошибки UNION — модель читает карту и собирает ОДИН точный payload.
9. **Раунд-2 фикс мусора**: `_clean_secret_value` отбрасывает HTML/URL
   фрагменты (кавычки, угловые скобки, `attr=`, `://`, ведущий `/`) —
   ловушка «слово „ключ“ на странице + `=` в HTML-атрибуте» больше не
   даёт фейковых секретов.
10. **Phase 5 — UNION-извлечение** с флаговыми колонками
    `pass/pwd/pin/code/key` — флаг может быть самим ключом админа;
    аварийный хвост `__main__` не перезаписывает непустой flag.txt, всегда
    exit 0.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `inventory`, `read_file`, `grep_files` | разведка материалов |
| `http` / `http_batch` | GET с авто-cookie; до 60 путей параллельно |
| `http_post` | POST без auto-follow; `data` verbatim (HPP), `headers` (инъекция в заголовки) |
| `login_probe` | главный инструмент: мульти-формовое дискавери → QS → NB/HPP/HDR → source recon → SQLi-матрицы (все семьи) → Phase 4 session follow → Phase 5 UNION |
| `set_cookie` | ручная подделка cookie (модель видит cookie_decoded) |
| `decode` | base64/hex/url (значение запоминается как evidence) |
| `finish` | завершение; decoy-guard по траст-тирам |

## Отличия от исходного P4Z8-агента (харденинг-дельты интеграции)

Код перенесён 1:1 (AST-сверка `scripts/ast_diff_p4z8.py`; единственное
исключение — `noqa` для унаследованного неиспользуемого `rec2`) с теми же
тремя харденинг-правками, что и у остальных агентов: realpath path-guard,
атомарная запись flag.txt, безопасная ошибка LLM-конфига; плюс v2
base64-автодекод (`decode_b64_flags` на `_response_record`, константа
`B64_CANDIDATE_RX`; импорт `base64` в `decode_value` поднят на верхний
уровень — модуль уже импортирован как `base64_mod`).

## Проверка

Offline-проверки не используют сеть: уязвимый сервис реализован в памяти на
**настоящем sqlite3** (мульти-формы, deny-инверсия, двухслойная проверка,
LIKE, hidden/select/textarea, CSRF-ротация, traversal, SSTI, HPP,
cookie-подделка, регистрация); модель скриптуется; `_probe_url` заглушен.

```powershell
pytest -q tests/test_vega_p4z8.py
```

50 тестов: контракт архива (сборка `build_p4z8`, manifest, атомарная запись,
hardened guard, crash-guard, маркеры раундов в исходнике), path-guard
(escape/sibling/symlink), безопасная ошибка конфигурации, `resolve_target`,
контракты разбора реплик, `unwrap_body`, `_clean_secret_value` (HTML-мусор),
FLAG_RX/SECRET_LINE_RX, `_try_decode_value` (слои url/b64/json), redirect-ги
арды, evidence/кэш, захват cookie без следования за 302, POST `data` verbatim
(HPP), слияние заголовков, `decode`, v2 base64-автодекод, мульти-формовый
парсинг (две формы на странице), hidden/select/textarea, `form_field_pair`
(одно-полевые), классификация payload'ов, `_source_secrets`,
decoy-guard/тиры/nb_leak, `set_cookie`, сценарии:

- **n1** классика (первый успех — рядовой, матрица доходит до админских);
- **n5** LIKE-маски (`%admin%` при логине `sysadmin`);
- **n6** публичный декой на странице отказа — контекст без from_success;
- **n7** UNION-извлечение из отдельной таблицы (blind, без админ-строки);
- **n8** флаг = ключ админа (колонка `is_admin`);
- **n9** парольная инъекция при санитизированном логине;
- **n10** deny-инверсия: победивший payload — AND-false, не OR;
- **n11/n12/n13** hidden-поле / `<select>` / `<textarea>`;
- **n14** двухслойная проверка — фабрикационная пара;
- **n15/n16** вторая форма на другой странице / две формы на одной;
- **n17** ротация CSRF — refresh + retry;
- **n18** path traversal (ключ — имя файла);
- **n19** SSTI (`{{7*7}}` → 49, `{{config}}` — дамп с флагом);
- **n20** HPP (валидация — первая копия, запрос — все);
- **n21** подделка неподписанной cookie (cookie_surgery);
- **n22** регистрация админа (ключ админа = флаг, UNION-дамп);

плюс отчёт при полном промахе и четыре сквозных сценария (верифицированный
finish + report.txt, decoy-guard → секрет из админ-ответа, auto-pilot,
resolve_target из instruction.md).

> Минимальный `agent.json` (`format: vega-agent-harness`) следует подтвердить
> реальным VEGA validator до публикации архива для конкретной инсталляции.
