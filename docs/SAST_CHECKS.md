# Проверка SAST, SQLi, LFI и RFI

Проверки предназначены для ветки `feature/sast-contours`. Общий запуск объединяет
существующие проверки SQLi, LFI, RFI и корректности ответа Semgrep.

## Одна команда

Запустите Docker Desktop и откройте терминал в корне этой рабочей копии.
После изменений исходников сначала пересоберите образ:

```powershell
docker compose build agent
docker compose --profile agent run --rm --no-deps --entrypoint python agent -m benchmark.verify_sast_regressions
```

Команда не поднимает HTTP-стенды, не вызывает LLM и не исполняет анализируемые
PHP/JS/Python-примеры. Нужен образ со включённым Semgrep.

## Что проверяется

| Проверка | Ожидаемый результат |
|---|---|
| `sast-contours` | 6 ожидаемых ID правил и все 12 исходников ровно по одному разу |
| `sast-sqli-hardening` | 6 находок по точным файлам, правилам и строкам |
| `sast-sqli-variants` | 14 находок, ноль на безопасных примерах |
| `sast-lfi-variants` | 14 находок, ноль на безопасных примерах |
| `sast-rfi-variants` | 14 находок, ноль на безопасных примерах |
| `scanner-contract` | чистый исходник принимается, пустой скан отклоняется, комментарии `nosemgrep` не скрывают SQLi/LFI/RFI |

Каждый набор использует реальный Semgrep и производственный SAST-парсер.
Проверяющие модули также контролируют состав просканированных файлов и ошибки
сканера. Это учебная регрессия, а не доказательство полноты обнаружения на любом
проекте. Непустой список просканированных файлов не означает полного покрытия.

## Где смотреть результат

- `logs/sast-regression/summary.json` — общий статус и все шесть результатов.
- В той же папке — исходные JSON-ответы Semgrep для пяти наборов.
- Код завершения `0` означает прохождение всех проверок, `1` — хотя бы одну ошибку.
- После одной ошибки остальные наборы продолжают проверяться для диагностики.
- Перед сканированием старый итог заменяется статусом `running`.
- Для каждого набора сохраняется `pending`, `running`, `passed` или `failed`.
- При прерывании незавершённый отчёт остаётся `running`; это не успешная проверка.
- Отчёт обновляется через временный файл и атомарную замену, чтобы не читать обрезанный JSON.
- Читайте итоговый статус, а не старые JSON-файлы от предыдущих запусков.

В CI этот же запуск выполняется перед общим smoke-тестом, а отчёты сохраняются
как artifact `sast-regression-reports`, в том числе при ошибке проверки.

## Обычные Python-тесты

```powershell
python -m ruff check .
python -m ruff format --check .
New-Item -ItemType Directory -Force .validation | Out-Null
python -m pytest -q --basetemp=.validation/pytest-temp
```

Python-тесты проверяют обработку ошибок и код приложения. Они дополняют, но не
заменяют реальный скан. При провале интеграционной проверки сначала смотрите
пропущенные и неожиданные находки; ожидаемые результаты меняются только после
осознанного изменения сценариев, а не для получения зелёного статуса.

Формат ответа Semgrep описан в [SAST output contract](sast-output-contract.md).
