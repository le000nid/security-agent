# Арсенал v10: атака и защита в SAST-доменах (LFI, RFI, SQLI)

Арсенал — это парная бухгалтерия «вектор ↔ слой»: для каждой неочевидной
техники проникновения существует конкретный защитный механизм, и пара
доказывается кодом, а не декларацией. Каждая категория содержит наивную
песочницу (типовой «защищённый» код с реальными ловушками) и охраняемую
реализацию. Инвариант арсенала, проверяемый в CI:

> **атака без защиты обязана удаваться, защита обязана её останавливать**.
> Провал любой из двух половин — дефект дизайна (вектор теоретический или
> слой декоративный).

v10 развивает обе стороны сразу в двух направлениях:

- **комплексные цепочки** — многошаговые атаки, где обход строится из
  нескольких примитивов: TOCTOU, escape через `extractall`, symlink-члены
  внутри архивов, zip-бомбы, вложенные архивы, IPv4-mapped и scoped IPv6,
  redirect-циклы, доставка payload вторым хопом, `VACUUM INTO`,
  рекогносцировка схемы через рекурсивный CTE;
- **простой залп** — максимально широкий набор тривиальных написаний
  классических обходов: одиночное кодирование слэша, сырые `;` и `\`,
  полноширинные точки в обеих формах, NUL-зачистка, префикс `./`,
  uppercase-обёртка `FILE://`, семейство резервных копий (`~`, `.old`,
  `.swp`), `.env.local`, короткие формы IP (`127.1`, `127.0.1`), нулевые
  дополнения октетов, `[::0:1]`, `glob://`/`zip://`, underscore-wildcard,
  классическая UNION-выгрузка. Враг мог не предусмотреть любую из простых
  форм — арсенал проверяет их по отдельности.

- **LFI** — 31 вектор / 11 слоёв (CWE-22, CWE-23, CWE-59, CWE-367, CWE-409, CWE-538)
- **RFI/SSRF** — 26 векторов / 8 слоёв (CWE-918, CWE-601, CWE-93)
- **SQLI** — 21 вектор / 7 слоёв (CWE-89)

Всего 78 векторов. Ни один не покидает процесс: RFI использует симулятор
DNS и ответов, SQLI — настоящую SQLite-базу в каталоге песочницы, LFI —
реальные файлы, архивы и symlink во временном каталоге.

## Запуск

```powershell
python -m app.main arsenal --category all --mode campaign   # таблица вердиктов
python -m app.main arsenal --category sqli --mode matrix    # матрица вектор x слой
python -m app.main arsenal --mode docs                      # шпаргалка
python -m benchmark.verify_arsenal                          # CI: код-уровень
python -m benchmark.verify_arsenal_sast                     # CI: Semgrep-правила
```

Кампании также покрыты pytest-параметризацией (`tests/test_arsenal_*.py`):
каждый вектор прогоняется через обе реализации, проверяется и результат,
и то, что остановивший слой совпадает с проектным (`stopped_by`).

## Домен LFI (`app/agent/arsenal/lfi.py`)

Слои: **G1** декодирование до фикс-поинта до проверок; **G2** канонические
сегменты (NFKC до проверок, запрет `..`-сегментов и абсолютных подсказок);
**G3** запрет URI-обёрток, членов архивов (`#`) и glob-метасимволов;
**G4** белый список сегментов/суффиксов, dot-файлы и бэкапы запрещены;
**G5** запрет раскрытий (`$`, остаточные `%`); **G6** контейнерность после
realpath (symlink-хопы разрешаются до проверки); **G7** заморозка порядка —
после валидации каноническая форма не мутирует; **G8** согласованность
открытия (stat до, fstat после — подмена пути между проверкой и чтением
обнаруживается); **G9** санитизированная распаковка (поштучный проход:
родительские сегменты и не-регулярные члены отвергаются до записи);
**G10** лимиты амплитуды (размер члена и коэффициент сжатия);
**G11** запрет вложенных архивов.

Комплексные векторы v10: TOCTOU-подмена (`report.txt` меняется на symlink
между проверкой и открытием), escape через `extractall` без фильтра,
symlink-член внутри TAR с перезаписью внешнего файла «сквозь» ссылку,
zip-бомба (член 8 МБ из нулей, амплификация >1000x), вложенный архив
(zip-in-zip с `../`-членом во внутреннем слое). Простой залп v10:
`..%2f`, `%2e%2e\`, `．．/`, `%ef%bc%8e…`, `..%00%2f`, `./..%2f`, `..;/`,
`FILE://`, `config.py~`, `config.py.old`, `.config.py.swp`, `.env.local` —
плюс векторы v8 (`;`-прерывание, двойное декодирование, `\`-стык,
полноширинный NFKC, абсолютный путь, `$VAR`, symlink-хоп, члены ZIP/TAR,
`file://`, `.env`, `.bak`, glob).

## Домен RFI/SSRF (`app/agent/arsenal/rfi.py`)

Слои: **R1** строгая схема (после декодирования и свёртки — только
http/https); **R2** контроль authority (userinfo отделяется, контрольные
байты запрещены); **R3** канонизация хоста (десятичный/hex/восьмеричный/
короткий IP, любая форма IPv6, IPv4-mapped и scoped-адреса разбираются
`ipaddress` и проверяются на приватность); **R4** омоглиф-контроль
(NFKC + ASCII); **R5** egress-allowlist; **R6** запрет кросс-origin
редиректов; **R7** пин DNS-ответа с повторной проверкой IP; **R8** лимит
глубины редиректов (циклы и длинные цепочки не расходуют ресурсы).

Комплексные векторы v10: IPv4-mapped IPv6 в hex-форме (`[::ffff:7f00:1]`
не содержит «127.0.0.1»), link-local с зоной индекса (`[fe80::a1%25eth0]`),
цикл редиректов на доверенном хосте (клиент без лимита выжигает 20
переходов), доставка `data://`-payload вторым хопом (схему проверяют
только на первом), суффиксная маска домена
(`trusted.example.attacker.example`). Простой залп v10: `http://127.1/`,
`http://127.0.1/`, `http://0177.0000.0000.0001/`, `[::0:1]`,
`glob:///srv/*`, `zip:///etc/shadow` — плюс векторы v8 (userinfo-подмена,
редирект с доверенного хоста, табуляция в authority, длинная форма
IPv6-loopback, десятичный/hex/восьмеричный IP, percent-encoded authority,
DNS-rebinding, redirector, CRLF-инъекция, регистр/пробелы в схеме,
`data://`, `expect://`, IMDSv6).

## Домен SQLI (`app/agent/arsenal/sqli.py`)

Слои: **Q1** параметризация и закрытый реестр эндпоинтов (legacy-операции
удалены); **Q2** allowlist идентификаторов ORDER BY; **Q3** одно statement,
никакой DDL/PRAGMA/`VACUUM INTO` из входа; **Q4** канонизация входа
(декод + NFKC + запрет quote-класса и blob/char-конструкций); **Q5**
ESCAPE-маскирование LIKE; **Q6** повторная проверка значений из БД
(second-order); **Q7** запрет системных объектов в выражениях
(`sqlite_master`, `pragma_*`, административные операции).

Комплексные векторы v10: выгрузка всей таблицы одним агрегатом
(`group_concat` в UNION), запись копии БД в выбранное место
(`VACUUM INTO`), рекогносцировка схемы рекурсивным CTE по
`sqlite_master` (без единой кавычки), раскрытие колонок табличной
`pragma_table_info`, обход фильтра ключевых слов регистром
(`SeLeCt` против фильтра в нижнем регистре). Простой залп v10: классическая
UNION-выгрузка токенов и underscore-wildcard `_` в поиске — плюс векторы
v8 (тавтология, вход комментарием, декод после фильтра, полноширинная
кавычка, second-order, `%`-утечка, boolean-blind в ORDER BY,
PRAGMA-рекогносцировка, `ATTACH DATABASE`, blob-литерал `x'61646d696e'`,
`char(97,…)` в т.ч. в CTE-выгрузке, разбивка `/**/`, посимвольный
LIKE-оракул).

## SAST-слой

`config/semgrep-arsenal.yaml` — семь правил (f-string SQL, executescript
входа, `open(base + user)`, запись члена архива через `os.path.join`,
`urlopen(переменная)`, `extractall()` без валидации членов, `VACUUM INTO`
в f-string). Фикстуры: `targets/arsenal-{lfi,rfi,sqli}/` — в каждой
`vulnerable.py` обязан дать находку, `benign.py` — ни одной
(`benchmark/verify_arsenal_sast.py`). Правила намеренно regex/структурные,
чтобы вести себя одинаково на всех поддерживаемых версиях Semgrep.

## Как добавить новый вектор

1. Добавьте `Vector` в `VECTORS` домена с проектируемым `stopped_by`.
2. Постройте payload в `_build_payloads` и наивную ловушку в `naive_run`
   так, чтобы вектор на наивной реализации **срабатывал**.
3. Добавьте остановку в `guarded_run` (при необходимости — новый слой
   в `LAYERS` с кодом, а не описанием).
4. Запустите `python -m benchmark.verify_arsenal` — кампания обязана
   показать «защита впереди атаки» по всем векторам.
