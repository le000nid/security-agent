# VEGA P2Z3 agent («Проект помнит прошлое»)

`vega_p2z3/` — автономный экспорт для тестовой системы VEGA: агент поколения
P2Z3, который восстанавливает секрет, удалённый из кода проекта в одном из
прошлых коммитов, и записывает его точное значение в
`$VEGA_CTF_ARTIFACT_DIR/flag.txt`. Как и [базовый VEGA adapter](VEGA.md), он
не меняет SAST/DAST pipeline, benchmark или правила основного приложения и
поставляется отдельным архивом без зависимостей (только стандартная
библиотека Python).

Все экспорты собираются одной командой:

```powershell
python scripts/build_vega.py
```

Результат: `dist/security-agent-p2z3.zip` и остальные профили. В корне
каждого архива находятся ровно `run.sh`, `agent.json`, `agent.py`,
`strategy.md`.

## Архитектура

Агент использует проверенную архитектуру серии (P2Z1/P2Z3/P2Z4/P2Z5):
компактный LLM-цикл с инструментами, где модель расследует, инструменты
исполняют, а `finish` проверяется против множества текущих непустых строк
worktree.

```text
instruction.md + materials + .git -> LLM (30 шагов, окно 14 сообщений,
        дедлайн 520 c)
        -> одно JSON-действие -> инструмент -> наблюдение -> LLM ...
        -> finish -> проверка "значения нет в текущих файлах" -> flag.txt
```

Ключевая валидация результата: секрет, который ещё присутствует в текущем
непустом файле, — это заглушка или decoy, а не ответ. Настоящий ответ —
значение, удалённое из истории (`git log --all --full-history -p`,
`git cat-file --batch-all-objects`, raw-объекты `.git/objects`).

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `inventory` | список файлов и найденных Git-репозиториев в materials |
| `read_file`, `grep_files` | чтение и поиск по materials (включая `.gz`) |
| `git_log` | форензика: история пустых файлов, удалённые строки в диффах всех коммитов (+reflog), интересные объекты |
| `git_find` | поиск по паттерну в диффах и объектах |
| `git_show` | конкретный коммит/файл (ревизия валидируется по whitelist-regex) |
| `git_objects` | сырые объекты `.git/objects` (zlib), reflog, `COMMIT_EDITMSG`, `packed-refs` |
| `decode` | base64/hex/url |
| `finish` | завершение; значение не должно присутствовать в текущих непустых файлах |

Ранжирование кандидатов (приоритеты 50–100): строки из истории файлов,
которые сейчас пусты (`[FROM_EMPTY_FILE]`, приоритет 95–100), flag-shaped
значения из объектов (92), assignments из объектов (80), прочие удалённые
строки (50–85). Декодированные base64-хиты добавляются в `EVIDENCE` и
участвуют в фолбэке.

## Границы безопасности

- файловые операции остаются внутри canonical `MATERIALS` и окружающего
  `VEGA_TASK_DIR` (Git-метаданные лежат там); guard использует `realpath` и
  строгую проверку родителей — symlink- и sibling-directory escape
  отклоняются;
- Git вызывается только через `subprocess.run` с `shell=False`,
  фиксированными списками аргументов и `GIT_TERMINAL_PROMPT=0`; ревизии
  `git_show` проходят whitelist-regex;
- ответы и наблюдения обрезаются (`clip`), цикл ограничен 30 шагами и
  дедлайном 520 секунд;
- stderr не содержит содержимого реплик и значений флага (только имена
  шагов); инструкции из материалов — недоверенные данные;
- артефакт пишется атомарно (tmp + replace) и содержит только значение
  флага без дополнительного текста;
- недостающая конфигурация LLM (`OPENAI_BASE_URL`, `OPENAI_API_KEY`,
  `LOCAL_AGENT_MODEL`) даёт одну безопасную ошибку без секретов в сообщении.

## Отличия от исходного P2Z3-агента

Код логики перенесён 1:1 и приведён к стандартам проекта: Ruff-форматирование
и четыре харденинг-правки платформы v2:

1. `safe_material_path` — `realpath` + строгая проверка родителей вместо
   `resolve` на объединённом пути (sibling-каталог рядом с task dir больше
   не проходит guard); symlink-escape отклоняется.
2. `write_artifact` — атомарная запись через временный файл и `os.replace`;
   фолбэк `__main__` использует ту же функцию.
3. `model` — отсутствующие переменные окружения дают безопасный
   `RuntimeError` с именем переменной вместо сырого traceback.
4. `decode_b64_flags` + `B64_CANDIDATE_RX` — base64-автодекод блобов
   (≥24 символа) в каждом наблюдении, попавшем в `EVIDENCE`; секрет,
   спрятанный в base64 внутри Git-истории, попадает в кандидаты фолбэка.

## Проверка

Offline-проверки не используют сеть (правило `tests/conftest.py`): модель
скриптуется, Git-репозиторий создаётся в tmp через `git init`.

```powershell
pytest -q tests/test_vega_p2z3.py
```

Покрывается: контракт архива и manifest, path-guard (escape/sibling/symlink),
разбор ответов модели (`action_from_text` во всех формах, включая
блоки ```json и prose), безопасная ошибка конфигурации, контракты
`decode_value`/`decode_b64_flags`/`clean_secret_line`, git-форензика на
настоящем репозитории (секрет в коммите 1, файл очищен в коммите 2),
e2e-циклы: подтверждённый finish, отклонение значения, которое всё ещё
есть в текущих файлах, и фолбэк по кандидатам при недоступной модели.
