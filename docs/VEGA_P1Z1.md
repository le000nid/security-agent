# VEGA P1Z1: самостоятельный агент

Модуль `app/vega_p1z1` решает задачу «Первый запуск»: сам обходит каталог
`VEGA_TASK_DIR/materials`, передаёт содержимое модели через шлюз VEGA и сохраняет
выбранное значение в `VEGA_CTF_ARTIFACT_DIR/flag.txt`. Это отдельный запуск
внутри проекта, который использует тот же код, что и самостоятельный ZIP.

```powershell
python -m app.main vega-p1z1
python -m app.main vega-p1z1 --package dist/vega-p1z1.zip
```

Архив содержит ровно четыре файла в корне: `run.sh`, `agent.json`, `agent.py`,
`strategy.md`. Запуск: `bash run.sh`. Семейство среды VEGA, доступное в разделе
«Компиляторы», использует Python 3.12. ZIP требует только стандартную библиотеку:
Semgrep, Nuclei, Docker и зависимости основного приложения в нём не нужны.

## Настройки запуска

Все значения выдаёт среда VEGA:

- `VEGA_TASK_DIR` — каталог задания с подкаталогом `materials`;
- `VEGA_CTF_ARTIFACT_DIR` — каталог для результата;
- `OPENAI_BASE_URL` — базовый адрес шлюза, к нему добавляется `/chat/completions`;
- `OPENAI_API_KEY` — служебный ключ шлюза;
- `LOCAL_AGENT_MODEL` — имя модели;
- `VEGA_AGENT_SESSION_ID` — значение заголовка `X-VEGA-Agent-Session`.

Личный API-ключ в исходники или архив не добавляется. Настройки LLM основного
проекта не подставляются вместо настроек VEGA. В ZIP нет `.env` и сетевых установок.

## Как выбирается значение

Модель получает все прочитанные тексты с идентификаторами файлов. Она должна
вернуть JSON с `file_id` и `value`. Программа принимает только непустое значение,
которое дословно присутствует в указанном файле. Имена файлов, формат и значение
ключа не зашиты. Выбор по смыслу выполняет модель, поэтому корректность на
неизвестных данных зависит и от её ответа; проверка подстроки не доказывает,
что модель выбрала правильный секрет.

Содержимое файлов считается данными, не командами. Исходники не исполняются,
переходы по URL из материалов не выполняются. Символические ссылки и бинарные
файлы пропускаются. Поддерживаются UTF-8 с BOM и без него, а также Windows-1251.
Ограничения: 64 текстовых файла, 64 КиБ на файл, 120000 символов суммарно,
до трёх запросов с таймаутом до 45 секунд и бюджетом приложения 170 секунд.
При превышении лимита контекст не обрезается молча: запуск завершается ошибкой.

Успех возможен только после ответа модели и проверки выбранного значения.
Пустой ответ, ошибка шлюза или выдуманное значение не дают успешный результат.
Флаг записывается в UTF-8 без добавления перевода строки. Старый `flag.txt`
удаляется перед попыткой, чтобы не выдавать старый результат за новый.
Ключ, содержимое файлов и ответ модели в журналы не печатаются.

## Метаданные и проверка

`agent.json` — метаданные нашего приложения с именем, версией и `entrypoint`.
В предоставленном PDF дополнительная схема JSON не опубликована; формат не
выдаётся за подтверждённую внутреннюю схему валидатора VEGA.

Тесты проверяют протокол запроса, выбор значения из исходника, ошибки и упаковку.
`python -m benchmark.verify_vega_p1z1` дополнительно извлекает ZIP и запускает
`bash run.sh` с локальным имитатором шлюза. Это проверка HTTP и исполнения,
а не реальная модель и не успешная сдача в VEGA. Автоматическая сдача на сайте
не выполняется.

Локальная проверка 27 октября 2026: полный прогон проекта — 621 passed,
3 skipped; все 7 SAST-проверок и Ruff прошли. Распакованный ZIP проверен
в Python 3.12.3 с лимитом 512 МиБ и без внешней сети, на локальном имитаторе
шлюза. Подтверждены заголовки, повторы, точные байты флага и удаление старого
результата при ошибке. Проверена также сборка ZIP из установленного wheel.
