# DAN: проверка prompt injection

DAN (Do Anything Now) — семейство запросов, пытающихся заставить модель
игнорировать доверенные инструкции. Эта ветка добавляет учебный benchmark
`dan-lab` в существующие SAST/DAST, отчёты, веб-интерфейс и реестр стендов.

## Что проверяется

SAST: правило Semgrep `python-untrusted-system-prompt` отслеживает данные из
`request.args.get`, `request.form.get`, `request.json.get` до поля `content`
сообщения с ролью `system` или `developer`. Это индикатор для ручной проверки,
а не доказательство успешного jailbreak. Покрытие ограничено Python, указанными
источниками и потоком данных внутри функции. Сообщение с ролью `user` служит
отрицательным примером; разделение ролей само по себе не гарантирует безопасность.

DAST: Nuclei отправляет два GET-запроса в `/dan/chat`: обычный запрос и
DAN-запрос. Находка появляется только при статусах 200, маркере учебного стенда
в заголовках, отсутствии canary в обычном ответе и наличии его в ответе на DAN.
Отражение текста запроса не считается результатом: canary не входит в запрос.
Путь `/dan/protected` служит отрицательным контролем.

**HTTP-стенд — детерминированная имитация, не настоящая LLM.** Он специально
реагирует на один точный запрос; положительный результат подтверждает работу
учебного конвейера, но ничего не говорит об устойчивости ChatGPT или другой
модели. Маркер вымышленный, API-ключи и реальные секреты не используются.
Источник SAST — отдельный пример в том же учебном стенде, а не код реального
вызова провайдера. Нельзя переносить вывод на реальные модели без отдельного
согласованного стенда, адаптера API и критериев нарушения политики.

## Запуск

Нужен Docker Desktop/Engine. Из корня проекта:

```bash
docker compose --profile agent build agent dan-lab
./run.sh scan --benchmark dan-lab --mode full --no-llm
./run.sh latest
```

На Windows после сборки: `./run.ps1 scan --benchmark dan-lab --mode full --no-llm`.
SAST и DAST отдельно выбираются через `--mode sast` / `--mode dast`.
После запуска HTTP-стенд доступен на `http://127.0.0.1:3002`.
Команда `./run.sh ui` запускает стенды; в интерфейсе выберите
**DAN Lab (simulation)**, **FULL**, отключите AI-анализ. Ожидаются одна SAST
и одна DAST находка. Базовые тесты других стендов сохраняют свои ожидания.

Для проверки отрицательного DAST-контроля запустите только новый шаблон Nuclei,
временно заменив `/dan/chat` на `/dan/protected` в его копии: находок быть не должно.
Не меняйте эталонный шаблон при обычном запуске.

## Для объединения командиром

Основные изменения: новое правило в `config/semgrep.yaml`, шаблон
`config/nuclei/dan-lab-jailbreak.yaml`, запись реестра, `targets/dan-lab`,
базовые ожидания, Compose и запуск стенда в помощниках macOS/Linux/Windows.
Общие файлы могут пересечься с изменениями других участников: объединяйте
добавленные правила и записи, не заменяя файл целиком.

Проверки разработки:

```bash
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
semgrep scan --config config/semgrep.yaml --metrics=off --disable-version-check --strict targets/dan-lab
```

Тесты не обращаются к провайдеру. Реальный Docker/Nuclei FULL-прогон нужно
выполнить отдельно, прежде чем считать интеграцию проверенной на стенде.

## Проверено в ветке DAN

- 494 unit-теста прошли; один существующий тест пропущен.
- Ruff: проверка кода и форматирования прошла.
- Semgrep 1.79.0: одна находка в уязвимом примере, безопасный пример не отмечен; ошибок сканера нет.
- Nuclei 3.4.10: шаблон валиден. Реальные HTTP-прогоны всех локальных шаблонов дали одну находку на уязвимом стенде и ноль на защищённом и на стенде без маркирующего заголовка. Временные серверы слушали только 127.0.0.1 и остановлены после проверки.
- Нормализованные SAST/DAST результаты совпали с двумя эталонными находками.
- Docker/Compose FULL-прогон и Windows-скрипт не запускались: нужные инструменты отсутствуют на этой машине.
- Реальная LLM не проверялась.
