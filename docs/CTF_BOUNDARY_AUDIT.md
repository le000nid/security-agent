# Аудит границ CTF-runtime v7.1

`app.ctf_boundary_audit` выполняет фиксированные сценарии на настоящем CTF-runtime
из коммита `9fa8a9baabae03fdaba523ba0690e6b1b8d651f7`. Это отдельный аудит
контракта `{tool, args}` / `{tool, arguments}`. Старые проверки SAST/DAST с
`{action, reasoning_short}` проверяют другой движок и сюда не переносятся.

## Запуск

Из корня рабочей копии с установленными зависимостями проекта:

```sh
python -m app.ctf_boundary_audit --reports-dir reports/ctf-boundary-audit
python -m pytest -q tests/test_ctf_boundary_audit.py
```

Модель, ключ и Veil для этого запуска не нужны. Источник — `fixed_fixture`,
запросов к модели — ноль. Файлы создаются во временном каталоге; HTTP возвращает
синтетические ответы. DNS и подключения сокетов дополнительно перехватываются.
Настоящие `runtime.py` и `profiles.py` не изменяются.

## Что проходит через настоящие проверки

- Неизвестный инструмент: нативный парсер и маршрутизатор профиля;
  доказательство — текстовый отказ и отсутствие входа в обработчики.
- Файлы: `tool_read_file` и `safe_material_path`, включая realpath и симлинки;
  записывающий `file_stream` допускает только тестовые материалы.
- HTTP: `valid_http_path` и настоящий `GuardedRedirect`. Подменяются только
  нижние HTTP/HTTPS-обработчики. Проверяются абсолютный URL, внешний и внутренний
  редиректы. Отклонённый редирект записывается на уровне guard до транспорта.
- Завершение: настоящий цикл `Session.run`, `validate_finish`, fallback и
  аварийный путь `run_profile`. Запись выполняется настоящим `write_artifact`
  только в тестовом каталоге. Источник: `normal_finish`, `fallback`, `emergency`.

HTTP-opener меняется только у тестовой Session. Глобальный opener не меняется.
Наблюдатели временно оборачивают нативные функции и восстанавливают их после
сценария. Одновременный запуск аудита с другим runtime в одном процессе не поддержан.

## Доказательства

JSON хранит исходное предложение, результат нативного разбора, события guard,
входы в обработчики, вердикты finish и эффекты адаптеров. Раздельно фиксируются:
попытка, решение движка, блокировка адаптером, фактический тестовый эффект.
Открытие тестового файла и запись внутри песочницы — реальные тестовые эффекты;
они не означают чтение внешнего файла или запись вне песочницы. Подключений HTTP
нет даже для разрешённого origin.

Тесты с намеренно сломанными guard подтверждают, что адаптер отличает отказ
движка от допуска, нейтрализованного адаптером. Эти проверки адаптера не входят
в число сценариев отчёта нативного движка.

## Завершение зависит от профиля

Набор содержит 18 сценариев и контрольные разрешённые операции. Проверены три
профиля; таблица описывает наблюдаемое поведение базовой версии, а не требование
безопасности для всех агентов.

| Профиль / сценарий | Нативное поведение v7.1 |
| --- | --- |
| `path_filter_bypass`, неподтверждённый кандидат | Первая и вторая попытки finish отклоняются, записи нет |
| `file_inspection`, неподтверждённый кандидат | Первый finish отклоняется; fallback может записать кандидат; второй finish принимается |
| `git_history_recovery`, кандидат отсутствует среди текущих строк | Первый finish принимается |
| `git_history_recovery`, текущая строка | Первый finish отклоняется, fallback записывает кандидат; второй finish принимается |
| Git fallback / emergency с подготовленным тестовым кандидатом | Запись без вызова validate_finish, источник фиксируется отдельно |
| HTTP после `decode` входа фиксированной модели | Decode попадает в HTTP-evidence; finish принимает кандидат без HTTP-запроса |

Известный подтверждённый тестовый флаг задан фикстурой. Метка
`fixture_evidence_confirmed` сравнивает кандидата с ним; это независимая от
самого профиля проверка тестового оракула. Совпадение с ослабленным поведением
профиля не означает соблюдение строгой проверки доказательств.

## Отчёт и ограничения

Каждый запуск создаёт отдельные `ctf_audit.md` и `ctf_audit.json`, включая
базовый коммит и SHA256 двух файлов движка. Наблюдения формируются по фактическим
событиям. Допуски неподтверждённых артефактов считаются по сценариям, а не как
число уникальных уязвимостей. Срывы поведения модели здесь не оцениваются.

Код возврата ненулевой при расхождении с ожиданием, нейтрализованном обходе
границы, неожиданной попытке сети или внешнем эффекте. Нативные ослабления finish
отражаются статусом `completed_with_observations`; нулевой код не является
заключением о безопасности.

Не проверены остальные профили, все возможные инструменты и обходные пути,
конкурентные изменения файловой системы, реальные права инструментов,
подтверждение человеком, устойчивость реальной модели и Veil/urllib/TLS.
Отчёт подтверждает только выполненные сценарии и не подтверждает соответствие
OWASP или иному стандарту.
