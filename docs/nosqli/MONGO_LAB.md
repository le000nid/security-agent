# NoSQLi: стенд с MongoDB

Первое расширение предыдущей проверки Juice Shop.
Добавлены настоящий MongoDB API, три сценария, безопасные пары,
два SAST-правила, три DAST-шаблона и проверки результатов.

## Сценарии

| Сценарий | Что нарушено | Как исправлено |
|---|---|---|
| `operator` | API ждёт строку `sku`, но принимает объект с оператором | Проверка типа и длины, отклонение лишних полей, явное строковое значение |
| `filter` | Пользователь управляет всем фильтром вместо одного разрешённого поля | Новый фильтр только из разрешённого строкового поля |
| `scope` | Пользовательский фильтр перезаписывает серверного владельца Alice | Владелец задаётся сервером, пользователь может сузить выборку только по SKU |

Это три сценария двух родственных механизмов. Они не покрывают все NoSQLi.
Проверки только читают данные. API представляет учебного пользователя Alice;
полноценная авторизация здесь не реализована. Записи полностью синтетические.

## Быстрый запуск и проверка

Нужны Docker Desktop с WSL-интеграцией либо Docker Engine и Compose v2.
Команды выполняются в Bash из корня репозитория.

```bash
bash scripts/check-nosqli.sh
```

Скрипт останавливается при первой ошибке и последовательно:
1. Проверяет конфигурацию Compose и собирает образы.
2. Запускает MongoDB и API, ждёт их healthcheck.
3. Запускает Node.js-тесты с настоящей базой.
4. Проверяет обычные, изменённые и контрольные запросы к обоим вариантам API.
5. Проверяет настоящим Nuclei подготовленные HTTP-примеры, включая ложные срабатывания.
6. Запускает общий агент в FULL без LLM.
7. Проверяет шесть находок, точные места SAST, доказательства и отсутствие вызовов LLM.

Ожидаемый итог: `NoSQLi acceptance checks passed`.
API доступен на `http://localhost:3005`, MongoDB не публикует порт на хост.
База подключена к отдельной внутренней сети.

При ошибке прав на `runs` проверить владельца каталога. Скрипт использует
UID/GID текущего пользователя и не меняет владельцев автоматически.

## Повторный запуск агента

После первой успешной проверки:

```bash
export AGENT_UID="$(id -u)"
export AGENT_GID="$(id -g)"

docker compose -f docker-compose.yml -f docker-compose.nosqli.yml \
  --profile agent --profile nosqli-mongo run --rm --no-deps \
  agent scan --benchmark nosqli-mongo-full --mode full --no-llm
```

Для отдельных этапов заменить `--mode full` на `--mode sast` или `--mode dast`.
SAST читает именно исходники работающего API в `targets/nosqli-lab/src`.
Набор виден в существующем реестре benchmark и доступен через общий API интерфейса.

Ожидаются 3 SAST-находки и 3 DAST-находки. Общий evaluator считает уникальные
типы находок, поэтому его `expected_count` равен 5: одно SAST-правило срабатывает
в двух местах. `verify_nosqli_run` дополнительно проверяет все 6 экземпляров.

Путь к `report.md`, `findings.json` и `summary.json` выводится в терминале.
DAST-доказательство содержит обычный, изменённый и контрольный ответы.
Файл `runs/nosqli-http-acceptance.json` содержит сравнение ID записей.

## Ручной пример

Обычный поиск:

```bash
curl -sS http://localhost:3005/vulnerable/operator \
  -H 'Content-Type: application/json' -d '{"sku":"APPLE"}'
```

Объект вместо строки:

```bash
curl -sS http://localhost:3005/vulnerable/operator \
  -H 'Content-Type: application/json' -d '{"sku":{"$ne":"MISSING"}}'
```

Первый запрос возвращает Apple, второй — все три записи каталога.
Тот же второй запрос к `/safe/operator` должен дать HTTP 400.
Контроль со строкой `MISSING` даёт пустой список на обоих маршрутах.

## Что проверено

В среде разработки проверены настоящие Semgrep и Nuclei, нормализация,
Markdown-отчёт, структура Compose, Python-тесты и базовые Node.js-тесты.
Для Nuclei используются 9 HTTP-фикстур: положительная, безопасная, одинаковые
ответы, пустые результаты, HTTP 500, некорректный JSON, отражение ввода,
отсутствующая метка стенда и неверный Content-Type.

Полный скрипт прошёл на машине Степана 19 октября 2026:
9 Node.js-тестов без пропусков, 6 проверенных HTTP-вариантов,
3 SAST + 3 DAST в общем отчёте, 0 вызовов LLM.
Run: `20261019T133448Z-85f9690e25c7`.
Запуск GitHub Actions и слияние с остальными направлениями ещё не проверены.

## Ограничения

- DAST-шаблоны знают маршруты и учебные ID этого стенда. Это не универсальное
  обнаружение произвольных API. `route_prefix` позволяет проверить безопасные пары.
- SAST-правила сообщают потенциальную проблему. Свободный фильтр может быть
  разрешён контрактом другого API; такую находку нужно проверить вручную.
- Источники и операции SAST перечислены в правилах; все обёртки и потоки
  между функциями не покрыты. Строковое/числовое преобразование нейтрализует
  объектные операторы, но не доказывает безопасность другой логики приложения.
- Запросы ограничены размером входа, числом результатов и временем в базе.
- Сценарий с регулярными выражениями и aggregation пока не реализован.

## Остановка

```bash
docker compose -f docker-compose.yml -f docker-compose.nosqli.yml \
  --profile nosqli-mongo stop nosqli-mongo-api nosqli-mongo
```

Старые наборы `nosqli-sast`, `nosqli-dast` и Juice Shop остаются отдельными.
После изменения правил, Python-кода или реестра нужно пересобрать образ агента.

Справка: [совместимость MongoDB и драйверов](https://www.mongodb.com/docs/drivers/compatibility/),
[выпуск Node.js-драйвера 6.20](https://www.mongodb.com/docs/drivers/node/current/reference/release-notes/).
