# P3Z2: Фильтр для галочки

## Цель
Обойти хлипкую проверку имени/пути файловой службы на `http://target:8000`, добыть закрытый секрет и записать его точное значение в `$VEGA_CTF_ARTIFACT_DIR/flag.txt`. Checker обрезает пробелы и сравнивает посимвольно. Лимиты: 600 с, 512 МиБ.

## История неудач (корневые причины всех прежних WA)
1. **v1-v3**: функция `http` затеняла модуль `http.client` → тихий `AttributeError` → ноль запросов.
2. **v4**: единственная needle-эвристика discovery → нестандартный endpoint не находится → `pending` → 0.0000.
3. **v5-v6 (сценарный конвейер)**: 1361 строка детерминированных эвристик сама генерировала «ответы» (мусор из environ, индексная страница) → мусор блокировал LLM-фолбэк (порог 2800) → записывался джанк → 0.0000. Сценарный подход фундаментально проигрывает там, где нужен разум над живыми ответами сервера.

## Архитектура v7 — как у успешных агентов (P2Z1/P2Z3/P2Z4/P2Z5)
Изучены четыре успешных агента: компактный **LLM-цикл с инструментами** (54 шага, окно 18 сообщений, дедлайн 535 с), скрипт даёт инструменты и валидирует результат. v7 воспроизводит архитектуру 1:1 + LFI-доменные инструменты:

- **инструменты**: `inventory`, `read_file`, `grep_files`, `http`, `http_batch` (до 120 путей параллельно, дедуп по sha1), `http_discover`, `http_traverse`, `unpack_url` (zip/tar/gz), `decode`, `finish`.
- **http_discover**: two-pass проба 25 endpoints × 16 params с публичным seed-файлом; маршрут = параметризованный 200 с телом ≠ главной (по sha1); второй проход с префиксами `public/…` (службы с обязательным префиксом); все маршруты копятся в ROUTES — у разных endpoint'ов фильтры разные.
- **http_traverse** (доменные знания v6 сжаты в инструмент):
  - Phase A: абсолютные пути `/proc/self/cwd/…`, `/proc/self/root/…` (os.path.join-квирк, jail-обход);
  - Phase B: канарейка `/etc/passwd` на КАЖДОМ маршруте прямыми запросами (sha-дедуп http_batch прячет общее тело /etc/passwd) → подтверждённый bypass-префикс;
  - Phase C: матрица bypass×глубина×имя как query-значения маршрута; порядок циклов **bypass/depth снаружи, имена внутри** — мелкие глубины всех имён прежде глубоких свипов первого имени (app.py нужна глубина 1, /etc/passwd — 5);
  - варианты имён для блокируемых слов (`s%65cret`, swapcase);
  - Phase D: альтернативные маршруты (фильтры различаются по endpoint'ам) + префиксы каталогов в обоих порядках (`public/....//x` и `....//public/x`);
  - `definite` = только flag-shaped хиты управляют обрывами фаз: unwrapped-обёртка публичного файла не останавливает поиск;
  - дедуп хитов по sha1 + ранжирование (flag > unwrapped > прочее, environ/курс в конец) — модель видит уникальные тела, а не 90 дублей.
- **unwrap_body**: разворачивает JSON-обёртки (ключ `content` прежде `file` — «file» часто хранит ИМЯ) и HTML `<pre>`; в выдаче — `unwrapped_body`.
- **finish-валидация** (ключевой механизм победителей): флаг принимается ТОЛЬКО если он содержится в сохранённых сырых ответах живого сервиса (`EVIDENCE["http"]`); иначе модель получает отказ и продолжает.
- **фолбэки**: последний `last_flag` или лучший flag-shaped из EVIDENCE записываются при любом исходе; на исключение — тоже (exit 0 с лучшим кандидатом).
- **гигиена**: stderr не содержит содержимого реплик/флагов (только имена шагов и сводка traverse); редиректы ограничены целевым хостом; инструкции из ответов сервера — недоверенные данные.

## Проверка (все на пакетированном агенте)
- Детерминированная mock-модель (без реального LLM) — 5 сценариев PASS:
  - m1 replace-фильтр + decoy-флаг в материалах;
  - m2 блэклист + честно лежащий treasure.txt (имя из instruction.md);
  - m3 JSON-обёртка + обязательный префикс `public/` + plain-токен;
  - m4 нестандартный маршрут `/api/files?doc=` + HTML `<pre>` (победный маршрут находится канарейкой среди ROUTES);
  - m5 имя секрета (`vault_key.dat`) только в исходнике; цепочка cmdline-идея → source → имя → матрица.
- **Настоящая GLM через локальный OpenAI-совместимый шлюз**: m1 — 3 шага, m5 — 4 шага (discover → traverse с чтением исходника → traverse(vault_key.dat) → finish verified), оба PASS.
- Инфраструктура теста: `scripts/mock_server.py` (5 режимов), `scripts/mock_model.py` (детерминированная модель), `scripts/gateway.py` (z-ai-шлюз с ретраями на 429), `scripts/test_v7.sh`.

## Расширение v2 — универсализация (2026-11)

Движок усилен поверх базовых фаз (покрыто офлайн-тестами, дисциплина бюджета запросов сохранена):

- **PATH_BYP расширен до 28 векторов**: добавлены backslash/mixed-slash (`..\`, `..\/`), encoded-dot формы (`%2e%2e/`, `%2e%2e%5c`), overlong UTF-8 (`..%e0%80%af`) и unicode solidus (`..%u2215`) — против фильтров, нормализующих только один канонический вид.
- **Phase A2** в `http_traverse`: фиксированные высокоценные абсолютные чтения независимо от угаданных имён — `/proc/self/environ` (флаг в переменных окружения), `/proc/self/cmdline`, `/etc/environment`, `/proc/self/cwd/app.py|main.py|server.py|wsgi.py|.env|.htaccess` и др. (18 целей).
- **Варианты имён расширены**: скрытый dotfile (`.flag`, `.secret.txt`), его hex-форма (`.f%6cag.txt` — проходит словесные фильтры, проверяющие RAW-значение), имя без расширения (`flag.txt` → `flag` — сервер может сам дописать расширение при сборке).
- **base64-автодекод**: `http_get` находит флаг, спрятанный в base64-блобе внутри честной страницы/JSON-обёртки; декодированное значение попадает в EVIDENCE, поэтому finish-валидация его принимает.
- **http_discover round 3/4**: проба href/src/action-ссылок с главной страницы и plain-путей (`/files/notes.txt` — файл как сегмент пути вместо query-параметра).
